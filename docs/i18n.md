# Bilingual content

English uses `/en/` (for example `/en/events/` and `/en/blog/.../`). Traditional
Chinese uses `/zh-TW/` with the same English slugs. Existing unprefixed URLs
redirect to their English equivalents. GitHub Pages serves these static redirect
pages using an HTML meta refresh; the development server uses HTTP redirects. The URL is the language
selection; internal navigation preserves it. Both routes use the same templates
in `src/views/`. The deployment remains static on GitHub Pages.

## Interface text

Edit `src/i18n/messages.ts`. `en` is the complete source dictionary and `zhTW`
contains optional Chinese translations. Missing or blank Chinese strings use
English. Keep AI Safety, Alignment, Evals, Mechanistic Interpretability,
Scalable Oversight, Reward Hacking, Scheming, AI Control and AI Governance in
English. Translate the surrounding explanations naturally. Existing historical
articles have not been rewritten to enforce this vocabulary.

## Articles, events and team members

Keep the original record in `src/content/blog`, `events` or `team`. Its ID, slug,
dates, tags, authors, images, role and draft status are shared by both languages.
Translations are optional Markdown files under `src/content/translations/`:

```yaml
---
sourceCollection: events
sourceId: technical-paper-reading-fall-2026.md
locale: zh-TW
title: 2026 秋季 — Technical Paper Reading Group
description: 閱讀與討論 AI Safety 技術論文。
---

## 活動介紹

在此填入翻譯後的正文，AI Safety 術語保持英文。
```

`sourceId` is the original collection ID including `.md`. For example, a blog
post uses `general/welcome.md`, and a member uses
`organizers/ting-yu-amice-lin/index.md`. File names of translations do not affect
public URLs. Each source record may have at most one published translation per
language. Duplicate or missing source references fail the build.

Optional translated text fields are `title`, `description`, `summary` and `badge`.
Omit the body for a metadata-only translation. Omit fields that should fall back.
Set `draft: true` to keep a translation unpublished.

Fallback is independent for each text field and the complete Markdown body:

1. Requested language, if nonblank.
2. English translation, if nonblank.
3. Original record, for legacy content without an English version.

There is no automatic machine translation. A Chinese original will still appear
on the English route until an English translation is added. The article displays
an original-language or English-fallback notice when appropriate.

The source record's `bodyLanguage` is `en`, `zh-TW`, or `mul` (mixed). Events and
blog default to `mul`; team bios default to `en`. Set this accurately for new
records. A translated body's language is taken from its `locale`.

## Initial translations

The interface, homepage, About/FAQ, team section headings and photo captions have
Chinese text. Three Fall 2026 reading groups have Chinese titles/descriptions,
and `general/welcome` has a complete Chinese article. Other historical content
and member biographies retain their original text.

## Verification and preview

```sh
npm run check
npm run test:i18n
npm run build
npm run dev
```

Open `/zh-TW/` and use `EN / 繁中` to switch on the same page. Local preview does
not publish anything; production deployment still runs from `main` as before.
